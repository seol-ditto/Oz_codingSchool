# AI Health Web Assignment
- 과제 기간: 26.10.21 ~ 26.11.02
- 프로젝트 주제: 흉부 X-Ray 이미지 기반의 폐렴 판독 모델을 활용한 '폐렴 환자 관리 백오피스' 구축
    - 버전 관리 및 협업: Git & GitHub 시스템을 활용한 팀 프로젝트 버전 관리 및 협업 프로세스 숙달
    - AI 모델 서빙: FastAPI를 활용한 효율적인 인공지능 모델 서빙 API 구현
    - 백오피스 기능과 예측 결과 시각화(관리자 화면, 히트맵)
- 팀원: 김설아(팀장), 김지수, 이지희, 홍시윤
- 기술 스택
    - Backend: FastAPI, SQLAlchemy(async), Alembic
    - Database: MySQL
    - AI: PyTorch
    - 협업·환경: Git & GitHub, uv

<!-- 안내: 팀 규칙을 어떻게 정했고, 진행하면서 무엇을 바꿨는지 3~5줄 요약 (예: 리뷰어 마니또 방향 변경, 호출 받으면 이모지로 확인) -->

## 4. Git & GitHub 브랜치 전략
<!-- 안내: main / dev / 개인 브랜치 구조, 브랜치·커밋 이름 규칙, PR과 리뷰어 마니또, 공용 파일 구역 주석 방식 요약 -->
- Git Flow와 GitHub Flow를 함께 공부한 뒤, `main`과 `dev`를 유지하는 간소화한 Git Flow를 우리 팀의 브랜치 전략으로 채택
    - `main`: 최종 결과물, `dev`: 팀원 작업이 모이는 통합 브랜치
    - 위 브랜치 두 가지는 직접 push 금지!! (PR을 통해 머지하기)
    - 작업 브랜치는 항상 최신 `dev`에서 `feat/, fix/, docs/, refactor/` + 하는 일 + 이름으로 만들고, 머지가 완료되면 삭제
- 커밋 메세지는 팀 규칙에 따르기로 함
- 리뷰어 마니또로 리뷰어를 정해 최소 1명 승인 후 머지 진행 (본인 PR은 본인이 머지하지 않기)
    - `dev` -> `main` PR은 팀원 전원 확인 후 머지 진행
- 여러 명이 한 파일을 고칠 때는 주석으로 담당 구역 분리, 개인 작업을 모은 뒤 취합용 브랜치에서 양식 통일하고 `dev`로 최종 머지 진행(conflict를 줄이기 위해서)
- 디스코드 채널에 GitHub 웹훅을 연결해 PR 생성 및 리뷰 알림을 받을 수 있도록 함

- 자세한 내용: [브랜치 전략](docs/2일차_git_branch_전략.md), [Git & GitHub 규칙](docs/1일차_team_rules.md#git--github-rules)

## 5. 프로젝트 세팅
<!-- 안내: uv로 패키지 관리, MySQL·.env 설정, 모델 가중치(worker/models/) 준비, 서버 실행, 테스트 계정 만들기 순서로 요약 -->

- DB 마이그레이션: [3일차 DB 마이그레이션](docs/3일차_db_migration.md)
- 테스트 계정: [테스트 계정 가이드](docs/7일차_테스트계정_가이드.md)

### Alembic Migration Guide

이 프로젝트는 데이터베이스 마이그레이션을 위해 Alembic을 사용합니다.

#### 1. 마이그레이션 파일 생성 (자동 생성)
모델(`app/models/`)이 변경된 경우 다음 명령어를 실행하여 마이그레이션 파일을 생성합니다.
```bash
uv run alembic revision --autogenerate -m "변경 내용 설명"
```

#### 2. 데이터베이스에 반영
생성된 마이그레이션을 데이터베이스에 적용하려면 다음 명령어를 실행합니다.
```bash
uv run alembic upgrade head
```

#### 3. 이전 상태로 되돌리기 (Rollback)
마지막 마이그레이션을 취소하려면 다음 명령어를 실행합니다.
```bash
uv run alembic downgrade -1
```

### AI 모델 서빙
<!-- 안내: ResNet18(E8_lung_crop) 선정 이유, 전처리 흐름, 서버 시작 시 1번 로딩, Grad-CAM 히트맵, NFR 결과(Recall·Accuracy, 3초 이내) 요약 -->
- 모델 선정: 부트캠프 인공지능 트랙 DACON 흉부 X-Ray 폐렴 분류 해커톤에서 만든 모델 중 **ResNet18(`E8_lung_crop`)** 단독 모델 사용
    - 앙상블보다 Recall은 조금 낮지만, 가볍고 Grad-CAM 히트맵 코드가 이미 있어 3초 기준을 맞추기 용이하다고 판단
- 예측 흐름
    1. 흑백 변환 -> 비율 유지 224*224
    2. 테두리 검은 띠 제거
    3. torchxrayvision으로 폐 위치 찾기(폐를 못 찾으면 사진 전체 사용)
    4. 폐 영역 + 8% 여백만 잘라 224*224 사이즈 맞추기
    5. ResNet18로 폐렴 확률 계산 -> 0.5 이상이면 폐렴, confidence는 판정한 쪽(폐렴 or 정상)의 확률 * 100(퍼센트로 표현)
    6. Grad-CAM 히트맵 저장 (실패해도 예측 결과는 반환)
- 해커톤용에서 서버용으로 변경한 점
    - 서버 시작 시(lifespan) 모델을 한 번만 불러오고, 그때 가중치만 안전하게 읽음(`weight_only=True`)
    - 동시 요청이 들어와도 히트맵 계산이 섞이지 않도록 예측은 한 번에 하나씩 처리
    - 같은 진료기록 + 같은 모델의 결과가 있으면 다시 추론하지 않고 저장된 결과를 반환 (새로 예측하면 201, 저장 결과를 불러오면 200)
    - 가중치 파일은 GitHub에 올리지 않고 드라이브로 공유 -> 각자 `worker/models/`에 저장
- 결과
    - NFR-PRED-001: 검증 1,044장 기준 Recall 0.9742, Accuracy 0.9732 -> 최소 기준(Recall 0.90), 보조 기준(Accuracy 0.80) 모두 만족
    - NFR-PRED-002: 사진 1장 예측(전처리 + 폐 위치 찾기 + 예측 + 히트맵 저장까지) 첫 예측 0.80초, 이후 예측 평균 0.60초로 3초 기준 통과
    - 검증 사진 중 무작위로 정상 3장, 폐렴 3장을 선택해 해커톤 노트북(ipynb) 결과와 서버 결과 비교해보니 판정과 confidence가 완전히 동일하게 나오는 것 확인 완료
