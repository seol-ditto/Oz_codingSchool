# 7일차 테스트 계정 가이드

프론트 화면에 API를 연결하기 전에, **팀원 모두가 똑같은 테스트 계정 3개**를 각자 DB에 만들어 두기 위한 문서입니다.
이 문서만 순서대로 따라 하면 됩니다.

- 작성: 홍시윤
- 소요 시간: 약 10분
- 각자 로컬 DB에 만드는 계정이라, 다른 팀원 DB에는 영향이 없습니다.

---

## 1. 공통 테스트 계정

비밀번호는 셋 다 **`Test1234!`** 로 통일합니다.

| 이메일 | 비밀번호 | 이름 | 부서(department) | 최종 권한(role) | 용도 |
| --- | --- | --- | --- | --- | --- |
| `admin@test.com` | `Test1234!` | 테스트관리자 | `develop` | `admin` | 관리자 기능, 권한 변경 |
| `doctor@test.com` | `Test1234!` | 테스트의료진 | `medical` | `staff` | 환자·진료기록 등록, AI 예측 테스트 |
| `pending@test.com` | `Test1234!` | 테스트대기자 | `research` | `pending` | 403(접근 권한 없음) 화면 캡처용 |

> ⚠️ 이 계정과 비밀번호는 **로컬 테스트용**입니다. 실제 서비스에서는 절대 쓰지 않습니다.

가입 직후에는 셋 다 `pending`입니다. 아래 순서대로 `admin`과 `staff`로 바꿉니다. (`pending`은 그대로 둡니다.)

---

## 2. 시작 전 확인

아래가 되어 있지 않다면 먼저 해주세요.

- [ ] MySQL이 켜져 있고, `.env`의 DB 접속 정보(`DB_USER`, `DB_PASSWORD` 등)가 내 MySQL과 맞습니다.
- [ ] `.env`에 `SECRET_KEY`, `REFRESH_SECRET_KEY`가 서로 다른 값으로 들어 있습니다.
- [ ] 최신 `dev`를 받았고, 패키지를 설치했습니다.
  ```bash
  uv sync
  ```
- [ ] 테이블이 만들어져 있습니다. (프로젝트 폴더에서 실행)
  ```bash
  uv run alembic upgrade head
  ```
- [ ] AI 모델 가중치 파일이 있습니다. 팀 드라이브에서 `E8_lung_crop.pth`를 받아 프로젝트의 `worker/models/` 폴더에 넣습니다. (없으면 서버가 켜지다가 `FileNotFoundError: 모델 가중치가 없습니다`로 꺼집니다)

## 3. 따라 하기

### ① 서버 켜기

프로젝트 폴더(`pyproject.toml`이 있는 곳)에서 실행합니다.

```bash
uv run fastapi run app/main.py
```

- 가상환경을 직접 켜 둔 경우에는 `uv run` 없이 `fastapi run app/main.py`로도 됩니다.
- `Uvicorn running on http://0.0.0.0:8000` 같은 문구가 나오면 성공입니다.
- **이 터미널은 닫지 않고 그대로 둡니다.** (서버가 꺼집니다)

### ② 회원가입으로 계정 3개 만들기

브라우저에서 **http://0.0.0.0:8000/docs** 를 엽니다.

> `0.0.0.0` 주소가 열리지 않으면 `http://127.0.0.1:8000/docs` 로 들어갑니다. (Windows에서 자주 그렇습니다.)

`POST /api/v1/auth/signup` → **Try it out** → 아래 JSON을 하나씩 붙여넣고 **Execute**를 누릅니다. **3번 반복**합니다.

**1) 관리자 `admin@test.com`**
```json
{
  "email": "admin@test.com",
  "password": "Test1234!",
  "name": "테스트관리자",
  "department": "develop",
  "gender": "M",
  "phone_number": "010-0000-0001"
}
```

**2) 의료진 `doctor@test.com`**
```json
{
  "email": "doctor@test.com",
  "password": "Test1234!",
  "name": "테스트의료진",
  "department": "medical",
  "gender": "F",
  "phone_number": "010-0000-0002"
}
```

**3) 승인대기 `pending@test.com`**
```json
{
  "email": "pending@test.com",
  "password": "Test1234!",
  "name": "테스트대기자",
  "department": "research",
  "gender": "M",
  "phone_number": "010-0000-0003"
}
```

**성공하면** `201` 응답에 `"role": "pending"`, `"is_active": true`가 나옵니다.
```json
{
  "id": 1,
  "email": "admin@test.com",
  "name": "테스트관리자",
  "department": "develop",
  "gender": "M",
  "phone_number": "010-0000-0001",
  "role": "pending",
  "is_active": true
}
```

### ③ DB에서 `admin`만 관리자로 바꾸기

회원가입으로는 관리자를 만들 수 없어서, 이번 한 번만 DB에서 직접 바꿉니다.

**새 터미널**을 열어서 MySQL에 접속합니다. (서버를 켠 터미널은 그대로 둡니다.)

```bash
mysql -u root -p ai_health
```

- 비밀번호를 물으면 내 MySQL root 비밀번호를 입력합니다. (입력 글자는 화면에 안 보이는 게 정상입니다.)
- root에 비밀번호를 설정한 적이 없다면 `mysql -u root ai_health` 로 접속합니다.
- DBeaver 같은 프로그램을 쓰면 `ai_health` DB에서 아래 SQL을 실행해도 됩니다.

접속되면(`mysql>`) 아래를 실행합니다.

```sql
UPDATE users SET role = 'ADMIN' WHERE email = 'admin@test.com';
```

> ⚠️ **`'ADMIN'` 처럼 대문자로 써야 합니다.** DB에는 권한이 대문자로 저장됩니다. (`'admin'`처럼 소문자로 쓰면 오류가 나거나 반영되지 않을 수 있습니다.)

`Query OK, 1 rows affected`가 나오면 성공입니다. 잘 바뀌었는지 확인합니다.

```sql
SELECT id, email, role, department, is_active FROM users;
```

`admin@test.com`의 `role`이 `ADMIN`이면 됩니다. 확인이 끝나면 `exit`로 나옵니다.

### ④ `admin`으로 로그인해서 토큰 넣기

다시 `/docs` 화면으로 돌아옵니다.

1. `POST /api/v1/auth/login` → **Try it out** → 아래를 넣고 **Execute**
   ```json
   {
     "email": "admin@test.com",
     "password": "Test1234!"
   }
   ```
2. 응답의 **`access_token` 값**(`eyJ...`로 시작하는 긴 글자)을 복사합니다. 따옴표(`"`)는 빼고 복사합니다.
3. 화면 오른쪽 위의 **Authorize**(자물쇠) 버튼을 누릅니다.
4. 입력칸에 복사한 토큰을 붙여넣고 **Authorize** → **Close**
   - `Bearer ` 는 붙이지 않습니다. 토큰만 붙여넣으면 됩니다.

이제 API 오른쪽의 자물쇠가 잠긴 모양으로 바뀌면 `admin`으로 요청할 수 있는 상태입니다.

> 액세스 토큰은 **30분** 뒤에 만료됩니다. `401`이 나오면 로그인부터 다시 하고 토큰을 새로 넣습니다.

### ⑤ `doctor`의 id 확인하기

`GET /api/v1/admin/users` → **Try it out** → **Execute**

응답 목록에서 `"email": "doctor@test.com"` 항목을 찾아 **`id` 값**을 메모합니다.
(`search`에 `doctor`를 넣고 실행하면 한 명만 나와서 찾기 쉽습니다.)

### ⑥ `doctor`를 `staff`로 바꾸기

`PATCH /api/v1/admin/users/{user_id}/role` → **Try it out**

- `user_id` 칸에 ⑤에서 메모한 **doctor의 id**를 넣습니다.
- Request body에 아래를 넣고 **Execute**

```json
{
  "role": "staff"
}
```

`200` 응답에 `"role": "staff"`가 나오면 성공입니다.
```json
{
  "id": 2,
  "email": "doctor@test.com",
  "name": "테스트의료진",
  "role": "staff"
}
```

> 권한은 토큰이 아니라 DB에서 매번 확인하기 때문에, 바꾼 뒤 바로 적용됩니다.

### ⑦ 잘 됐는지 확인하기

1. `Authorize` 버튼 → **Logout** 으로 `admin` 토큰을 지웁니다.
2. `POST /api/v1/auth/login`으로 **`doctor@test.com`** 로그인 → `access_token` 복사
3. `Authorize`에 새 토큰을 붙여넣습니다.
4. `GET /api/v1/users/me` → **Execute**

**아래처럼 나오면 성공입니다.**
- `"role": "staff"`
- `"department": "medical"`

```json
{
  "name": "테스트의료진",
  "email": "doctor@test.com",
  "department": "medical",
  "gender": "F",
  "phone_number": "010-0000-0002",
  "role": "staff"
}
```

### (참고) `pending` 계정 확인하기

`pending@test.com`은 **그대로 둡니다.** 403 화면을 캡처하고 싶을 때는 다음과 같이 합니다.

1. `pending@test.com`으로 로그인 → 토큰을 `Authorize`에 넣기
2. `GET /api/v1/patients` → **Execute**
3. `403` 과 `{"detail": "접근 권한이 없습니다."}` 가 나오면 정상입니다.

## 4. 자주 나는 오류

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `401` `{"detail": "인증 정보가 유효하지 않습니다."}` | `Authorize`에 토큰을 안 넣었거나, 30분이 지나 만료됐거나, 토큰을 잘못 복사함 | 다시 로그인해서 `access_token`을 복사하고 `Authorize`에 넣기 (따옴표와 `Bearer ` 빼기) |
| `403` `{"detail": "접근 권한이 없습니다."}` | 계정이 아직 `pending`이라서 | `pending@test.com`이면 정상입니다. `admin`/`doctor`가 이렇게 나오면 ③ 또는 ⑥을 다시 확인 |
| `403` `{"detail": "관리자 권한이 필요합니다."}` | `admin`이 아닌 계정으로 `/api/v1/admin/...`을 호출함 | ③에서 `ADMIN` 반영 여부를 확인하고, `admin` 토큰으로 다시 `Authorize` |
| `403` `{"detail": "의료진만 등록할 수 있습니다."}` | `staff`이지만 부서가 `medical`이 아님 | `doctor@test.com`(`medical`)으로 로그인 |
| SQL 실행 오류 / 권한이 안 바뀜 | `role` 값을 소문자로 씀 | 대문자 `'ADMIN'`으로 쓰기 |
| `409` `{"detail": "이미 사용 중인 이메일입니다."}` | 이미 가입한 계정 | ②를 건너뛰고 ③부터 진행 |
| `409` `{"detail": "이미 사용 중인 휴대폰 번호입니다."}` | 내 DB에 같은 번호가 이미 있음 | JSON의 `phone_number`를 다른 번호로 바꾸기 |
| `422` | JSON 형식이 틀리거나 `department`, `gender` 값이 잘못됨 | 위 JSON을 그대로 복사해서 사용 (`department`는 `research` / `medical` / `develop`, `gender`는 `M` / `F`) |
| `500` + 서버 터미널에 `Access denied for user` | `.env`의 DB 계정 또는 비밀번호가 내 MySQL과 다름 | `.env`의 `DB_USER`, `DB_PASSWORD` 확인 후 서버 재시작 |
| `500` + `Table '...users' doesn't exist` | 테이블이 아직 없음 | `uv run alembic upgrade head` 실행 |
| 서버가 켜지지 않음 (`ModuleNotFoundError`) | 패키지 설치 안 됨 | `uv sync` 실행 |
| 서버가 켜지지 않음 (`SECRET_KEY` 관련 에러) | `.env`에 키가 없음 | `.env`에 `SECRET_KEY`, `REFRESH_SECRET_KEY` 추가 |
