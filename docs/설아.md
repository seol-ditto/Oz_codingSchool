# 브랜치 전략
- **여러 개발자가 하나의 저장소를 사용하는 환경**에서 저장소를 효과적으로 활용하기 위한 work-flow
- 브랜치의 생성, 삭제, 병합 등으로 협업에서 혼란을 최대한 줄이고 소스를 관리할 수 있도록

> 만약 브랜치 전략을 사용하지 않는다면?
- 어떤 브랜치가 가장 최신의 내용을 담고 있지?
- 어디에 내 작업물을 push해야하지?
- 새로운 작업을 시작할 때 어느 브랜치의 내용을 가져와야하지?

등의 혼란을 경험할 수 있다.

프로젝트를 진행할 때 코드 버전 관리를 위해 주로 Git과 GitHub를 사용하게 되는데 Git branch 전략은 대표적으로 두 가지가 있다.
| 전략 | 내용 |
| --- | --- |
| Git Flow | 제품 출시 버전, 개발 버전, 기능, 출시 준비, 버그 수정 등 다양한 branch 관리 |
| GitHub Flow | 하나의 기본 브랜치(**main**)과 여기에 기능을 추가하기 위한 브랜치(**feat** 등) **두 개**만으로 운영 |

이 중 먼저 GitHub Flow에 대해서 알아보았다.
