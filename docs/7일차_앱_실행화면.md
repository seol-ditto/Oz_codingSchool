## 9. 회원 목록 조회 (REQ-USER-004)

- 담당: 김설아
- API: GET /api/v1/admin/users
- 화면 경로: /admin/users (상단 메뉴 `회원 관리`, 관리자에게만 보임)
- 캡처
  - 성공: ![회원 목록 조회 성공](images/Day7_회원목록조회_성공.png)
  - 실패: ![회원 목록 조회 실패](images/Day7_회원목록조회_실패.png)
- 동작 설명:
  - `admin@test.com`으로 로그인하면 상단에 `회원 관리` 메뉴가 생기고, 누르면 `GET /api/v1/admin/users`를 호출해 전체 회원을 ID 순으로 표에 보여줍니다. (ID, 이름, 이메일, 부서, 전화번호, 권한, 상태)
  - 검색창에 이름 또는 이메일 일부를 입력하고 `검색`(또는 Enter)을 누르면 `?search=`가, 부서 선택 상자를 바꾸면 `?department=`가 붙어서 다시 조회합니다. 주소창에도 조건이 남아 새로고침해도 검색 조건이 유지되고, `초기화`를 누르면 전체 목록으로 돌아갑니다.
  - 조건에 맞는 회원이 없으면 표에 `검색 결과가 없습니다.`가 나옵니다.
  - 실패: 관리자가 아닌 계정(`doctor@test.com`)으로 `/admin/users`에 들어가면 `관리자 권한이 필요합니다.` 알림창이 뜨고 홈으로 이동합니다. 화면을 거치지 않고 API를 직접 호출해도 서버가 `403` `{"detail": "관리자 권한이 필요합니다."}`로 막습니다.

## 10. 회원 권한 변경 (REQ-USER-005)

- 담당: 김설아
- API: PATCH /api/v1/admin/users/{user_id}/role
- 화면 경로: /admin/users (회원 목록 표의 `권한` 열)
- 캡처
  - 성공: ![회원 권한 변경 성공](images/Day7_회원권한변경_성공.png)
  - 실패: ![회원 권한 변경 실패](images/Day7_회원권한변경_실패.png)
- 동작 설명:
  - 회원 목록 표의 `권한` 선택 상자에서 `승인대기` / `일반회원` / `관리자` 중 하나를 고르면 바로 `PATCH /api/v1/admin/users/{user_id}/role`에 `{"role": "staff"}` 같은 값을 보냅니다. (따로 저장 버튼 없음)
  - 성공하면 `권한이 변경되었습니다.` 알림창이 뜨고, 지금 걸려 있는 검색 조건 그대로 목록을 다시 불러와 바뀐 권한을 보여줍니다.
  - 권한은 토큰이 아니라 DB에서 매번 확인하므로, 예를 들어 `pending@test.com`을 `일반회원`으로 바꾸면 그 사용자가 다시 로그인하지 않아도 바로 환자 화면에 들어갈 수 있습니다.
  - 실패: 로그인한 관리자 본인 행의 선택 상자는 비활성화되어 있어 화면에서는 본인 권한을 바꿀 수 없습니다. API를 직접 호출하면 서버가 `400` `{"detail": "본인의 권한은 변경할 수 없습니다."}`로 막고, 없는 회원 id면 `404` `{"detail": "존재하지 않는 회원입니다."}`가 나옵니다. 화면에서 요청이 실패하면 `권한 변경 실패: (서버 메시지)` 알림창이 뜹니다.

## 17. 진료기록 목록 조회 (REQ-MDR-002)

- 담당: 김설아
- API: GET /api/v1/patients/{patient_id}/medical-records
- 화면 경로: /patients/{patient_id} (환자 상세 화면 아래쪽 진료기록 표)
- 캡처
  - 성공: ![진료기록 목록 조회 성공](images/Day7_진료기록목록조회_성공.png)
  - 실패: ![진료기록 목록 조회 실패](images/Day7_진료기록목록조회_실패.png)
- 동작 설명:
  - 환자 목록에서 `상세보기`를 누르면 환자 상세 화면으로 이동하면서 환자 정보와 함께 `GET /api/v1/patients/{patient_id}/medical-records`를 호출합니다.
  - 해당 환자의 진료기록을 최신 등록순으로 표에 보여줍니다. (ID, 차트 번호, 증상, 등록일시, `상세보기` 버튼)
  - 등록된 진료기록이 없으면 표에 `등록된 진료 기록이 없습니다.`가 나오고, `진료 기록 등록` 버튼으로 진료기록 등록 화면에 갈 수 있습니다.
  - 실패: 존재하지 않는 환자 번호로 주소를 직접 입력하면(예: `/patients/99999`) `존재하지 않는 환자입니다.` 오류 알림창과 오류 화면이 나옵니다. (API 응답 `404`) 승인대기(`pending`) 계정은 화면에서 `승인 대기 중인 사용자입니다.` 알림 후 홈으로 이동하고, API를 직접 호출하면 `403` `{"detail": "접근 권한이 없습니다."}`가 나옵니다.

## 18. 진료기록 상세 조회 (REQ-MDR-003)

- 담당: 김설아
- API: GET /api/v1/medical-records/{record_id}
- 화면 경로: /medical-records/{record_id}
- 캡처
  - 성공: ![진료기록 상세 조회 성공](images/Day7_진료기록상세조회_성공.png)
  - 실패: ![진료기록 상세 조회 실패](images/Day7_진료기록상세조회_실패.png)
- 동작 설명:
  - 환자 상세 화면의 진료기록 표에서 `상세보기`를 누르면 `GET /api/v1/medical-records/{record_id}`를 호출해 기록 ID, 차트 번호, 증상, 등록일시를 보여줍니다.
  - X-Ray 이미지는 비공개 폴더에 있어서 `GET /api/v1/medical-records/{record_id}/xray-image`로 로그인 확인 후 받아와 화면에 표시합니다. 이미지를 못 받으면 `X-Ray 이미지를 불러올 수 없습니다.` 문구로 바뀝니다.
  - 같은 화면에 저장된 AI 예측 결과 목록과 `AI 예측 결과보기` 버튼이 함께 나오고, `진료 목록으로` 버튼을 누르면 해당 환자 상세 화면으로 돌아갑니다.
  - 실패: 존재하지 않는 기록 번호로 주소를 직접 입력하면(예: `/medical-records/99999`) `존재하지 않는 진료기록입니다.` 오류 알림창과 오류 화면이 나옵니다. (API 응답 `404`)
