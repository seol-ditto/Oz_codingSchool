# 2026.10.22 목요일
- FastAPI 팀 과제 2일차
- 참석 인원: 4명

## 1. Git Flow & GitHub Flow 전략 공부하기
1. `dev` 브랜치에서 각자 `docs/이름`으로 브랜치 생성
2. 각자 공부한 내용 md 파일로 정리
3. commit 후 `dev` 브랜치로 PR 올리기
4. 팀 규칙에서 정한 서로의 reviewer 설정해서 리뷰 받기
5. `dev`에 4개의 md 파일 모인 것 확인 후 `docs/merge-summary` 브랜치 생성
6. 최종 취합본 생성(`2일차_git_branch_전략.md`) 생성하고 개별 파일 삭제
7. commit하고 PR 올리기
8. `dev`에 merge

## 2. 브랜치 전략을 통해 작업 내용 병합해보기
1. `dev` 브랜치에서 각자 `feat/이름`으로 브랜치 생성
2. API 요구사항 중 자신이 맡을 부분 선택
    - 시윤: 모든 회원의 정보를 목록으로 조회하는 API
    - 지수: 특정 회원의 정보를 삭제하는 API
    - 지희: 특정 회원의 정보를 조회하는 API
    - 설아: 회원의 정보를 입력받아 user_list에 추가하는 API, 입력받은 회원의 정보를 수정하는 API
3. `app/apis/practice_apis_이름.py` 파일을 생성하고 각자 작업 수행
4. `main.py`도 수정해서 FastAPI 서버를 로컬에서 실행
    - Swagger-UI 상 해당 API 확인되는지, API 테스트가 올바르게 동작하는지 확인
4. `main.py`를 제외하고 commit(conflict 방지)
5. PR 올리기

## 3. 과제 진행하며 느낀 점
- 브랜치 이름은 자세할수록 좋지만 너무 길면 switch할때 힘들다..
- 처음에 default branch를 `main`으로 두는 바람에 PR이 main으로 merge 되어버리는 불상사가 발생했다...
    - setting에서 default를 `dev`로 변경
- summit review에서 comment, approve 등의 차이를 모르겠다. 이건 github에 대해 더 공부해봐야 자세하게 팀원들에게 설명이 가능할 것 같음
