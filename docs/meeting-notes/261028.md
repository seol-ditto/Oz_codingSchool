- `16:30`까지 환자관리 API 설계 문서 팀원별 맡은 파트 작성 후 PR 열기
- 설계 통일 기준은 가장 먼저 PR을 올려주신 시윤님 파일을 보고 정함
    - 예시 값
        - 환자: 김오즈/F/27/`01012345678`
        - 날짜: `2026-10-27T14:30:00` 형식, `updated_at`은 수정 전에는 null
    - 요청 Headers는 `Authorization | Bearer {access_token}` 으로 통일
    - 성공 코드는 등록 201, 조회/수정/삭제 200
    - 실패 블록은 401 → 403(비활성) → 403(pending) → 403(의료진, 등록 API만) → 404 → 422 순서로 작성
- 템플릿 파일에 공통 사항 보완
    - id 구분⚠️ : `id`는 그 API가 다루는 대상의 ID이고, `patient_id`는 어느 환자의 것인지를 가리킴!!
    - 422 응답의 `ctx`는 글자 수 제한, enum 등 일부 오류에만 나오고, 명세서 예시에서는 생략 가능
- 환자 수정 응답은 상세 조회 응답과 같은 모양으로 정함
- PATCH에 빈 `{}`가 오면 4일차 회원 정보 수정과 똑같이 200 응답
