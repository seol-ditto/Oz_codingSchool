## 3. 과제 진행하며 느낀 점
- 처음으로 merge 과정에서 충돌이 발생했다!!
    - 다른 사람 구역 주석이 지워져서 그 영역을 침범하며 Conflict
    - 다음 작업부터는 뼈대 파일에서 본인 영역만 작성하기로 팀 회의시간에 공유
        - 커밋 전 `git diff`로 내 구역만 수정했는지 확인하기
    - 서로 import가 겹치는 경우에는 합치는 방향으로 결정(`Accept Both Changes`)
- Git에서 Conflict를 내는 기준
    1. 비교 방식
    Git은 합칠 때 세 가지 버전을 비교한다.

        1. 둘이 갈라지기 전의 원래 버전
        2. 내 브랜치 버전
        3. 상대 브랜치(dev 등) 버전

        원래 버전과 비교해서 한쪽만 바꾼 부분은 자동으로 반영, 양쪽이 같은 부분을 수정했을 때만 멈추고 충돌을 낸다.

    2. 충돌이 나는 경우
        1. 같은 줄을 둘 다 다르게 고쳤을 때: 둘 다 맨 위 `from fastapi import ...` 줄에 각자 필요한 걸 추가한 경우
        2. 붙어 있는 줄을 각자 고쳤을 때: 바뀐 곳 사이에 안 바뀐 줄이 하나도 없으면, Git이 같은 덩어리로 보고 충돌을 냄. -> 작업 구역 사이 빈 줄 2~3줄을 넣은 이유
        3. 같은 위치에 둘 다 새 줄을 넣었을 때: 예를 들어 둘 다 같은 구역 제목 바로 아래에 코드를 넣은 경우, Git이 어느 쪽을 먼저 두고, 어느 쪽을 다음 줄에 둘지 몰라서 conflict
        4. 누구는 파일을 고치고, 다른 누구는 그 파일을 삭제했을 때: `modify/delete` 충돌 발생
        5. 이미지같은 바이너리 파일을 둘 다 바꿨을 때: 줄 단위로 비교할 수 없어서, 조금만 달라도 conflict

    3. 주의사항⚠️
        1. 공백도 변경한 점이라고 친다! -> 들여쓰기, 줄 끝 공백, 빈 줄 하나만 달라도 같은 줄을 고친 것으로 보기 때문에 충돌 발생할 수 있음
        2. 충돌이 발생하지 않았다고 코드가 맞는 건 아님 -> 다른 줄에 같은 함수를 삽입하면 conflict는 나오지 않음!

    4. 충돌을 줄이는 방법
        1. 자주 `git pull origin dev`로 최신 파일 받아오기
        2. `import` 줄처럼 다같이 고치는 곳은 충돌이 나기 쉬우니, `Accept Both` 후 중복만 지우기
        3. PR을 오래 열어두지 않기!!! **리뷰어는 리뷰 요청이 오면 최대한 빨리 확인하자!**
