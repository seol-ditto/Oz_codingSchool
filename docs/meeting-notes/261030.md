## 2. 질문·답변
- Q. 스키마 작성 가이드의 `from_attributes=True` 규칙이 `users.py`에만 적용되는지? (시윤)
    - A. 모든 스키마 파일에 적용. DB 객체(SQLAlchemy)를 넘기는 응답 스키마에는 `model_config = ConfigDict(from_attributes=True)` 넣기
        - 스키마는 원래 딕셔너리만 받는데, DB에서 꺼낸 값은 객체라서 이 설정이 있어야 `.`으로 값을 꺼내 읽을 수 있음
        - `return result`처럼 그냥 반환하면 FastAPI가 알아서 읽어주지만, `model_validate()`로 직접 바꿀 때는 꼭 필요해서 통일해서 넣기로 함


## 3. 7일차 프론트 연결 팀 회의 결정 사항
1. 프론트 템플릿(`static/`)을 AI 에이전트로 우리 API에 맞게 연결
    - API 경로, 요청 모양, 선택 값(성별 `M/F`, 부서 `develop/medical/research`)을 우리 명세서에 맞춤
2. 화면 동작에 꼭 필요한 응답 필드 3개 추가 (요구사항 외 필드, 명세서 비고에 이유 적기)
    - 마이페이지 `id`: 회원 관리에서 본인 권한은 바꾸지 못하게 막는 용도
    - 회원 목록 `role`: 회원 관리 화면의 권한 선택칸 표시용
    - 진료기록 상세 `patient_id`: "진료 목록으로" 버튼으로 환자 상세로 돌아가는 용도
3. X-Ray·히트맵 이미지 파일은 로그인한 직원에게만 보내주는 API 2개 추가
    - `GET /api/v1/medical-records/{record_id}/xray-image`
    - `GET /api/v1/medical-records/{record_id}/heatmap`
    - 이미지는 공개 폴더가 아닌 `private_uploads/`에 있어서, 화면이 토큰을 붙여 받아온 뒤 표시
4. 테스트 계정은 각자 본인 DB에 만들기 (DB가 사람마다 따로라서)
    - 화면에서 회원가입 → 관리자 계정만 DBeaver에서 `UPDATE users SET role = 'ADMIN' WHERE email = 'admin@test.com';` (대문자 `ADMIN`)
    - 관리자로 로그인해서 나머지 계정은 회원 관리 화면에서 권한 변경
